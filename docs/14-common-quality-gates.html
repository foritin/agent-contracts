公共层质量门禁与验收向量

1. 为什么公共层需要独立门禁

共享模块的错误会同时扩大到 Charter 与 Tiny Hermes。公共层的质量门禁必须比单项目测试更早
发现“看似编译通过、语义已经分叉”的问题，例如：一个消费者把 ToolResult.is_error 当作
提示文本，另一个把它当作必须重试；或一个入口在取消时没有配对工具结果。

本页给出在没有任何现有源码的情况下也可执行的验收合同。具体接口请依次阅读
04-message-types、01-llm-provider、03-tool-host、02-session-management 和
12-api-contracts。

3. 最小测试向量

将以下向量做成无网络、可重复的 fixture。任何实现替换（例如更换 HTTP client、JSON 库或
MCP SDK）都必须通过它们。

3.1 消息与 Provider

text
V-MSG-01: User(Text) → Assistant(Text) → 序列化 → 反序列化，内容与 role 不变。
V-MSG-02: Assistant(ToolUse id=A) 后必须紧接 User(ToolResult id=A)。
V-MSG-03: 取消发生在 ToolUse 后、ToolResult 前时，补写 is_error=true 的 cancelled 结果。
V-PROV-01: stream 依次产生 TextDelta、ToolUse、Usage、Done；消费者不依赖网络分块边界。
V-PROV-02: provider 返回不可恢复错误时，流终结且错误带可展示分类，不泄露 API key。

3.2 ToolHost 与 MCP

text
V-TOOL-01: 未知工具默认拒绝或要求确认，绝不直接执行。
V-TOOL-02: 同名内置工具与 MCP 工具不碰撞；MCP 使用 server__tool 名称。
V-TOOL-03: stdio 子进程退出后，下一次调用返回可诊断错误，不使会话 writer 损坏。
V-TOOL-04: Streamable HTTP 的超时、非 2xx、非法 JSON 均映射为稳定错误类别。

3.3 会话、配置与压缩

text
V-STORE-01: JSONL 最后一行只写入一半时，恢复程序保留完整历史并报告截断。
V-STORE-02: 原子写入中断后，旧文件或新文件二者之一完整可读，绝不产生混合内容。
V-CFG-01: 默认值 < 配置文件 < 环境变量 < 显式参数的优先级固定且有测试。
V-CFG-02: 调试输出、错误、支持包都不得包含 api_key、authorization、cookie、token。
V-COMP-01: 压缩前后的最近 user 目标、未完成工具结果、持久事实均可追溯。

4. 兼容性与迁移测试

每一个落盘或跨进程数据结构都要有 schemaVersion、显式默认值和升级路径。

数据向后读取向前读取推荐策略
JSONL SessionEvent新实现读取旧事件旧实现可忽略新增可选字段tagged enum + 可选字段
配置 TOML缺失字段使用安全默认值未知字段保留或警告读改写时保留未知键
IPC JSON-RPCmethod / params 带版本不兼容时返回明确错误握手协商能力集
ToolSpec新字段不改变旧确认策略旧 consumer 不执行未知动作requires_confirmation 默认 true

迁移测试至少保留三个 fixture：最早支持版本、上一个版本、含未知字段的未来版本。不要只测试
“从当前版本写回当前版本”。

5. 性能与资源预算

公共层不应替应用层设定 UI 帧率，但必须设定可预期的资源边界：

  • 流式事件处理不得在每个 token 全量复制历史；会话追加应是线性写入。
  • JSONL 恢复必须支持流式读取，坏尾行不能使完整文件全部失效。
  • MCP server 的连接、重连和超时必须有可配置上限。
  • compaction 必须记录输入范围和摘要来源，不能成为不可审计的黑箱。
  • 所有 token / 字节 / 深度限制都应在 DTO 中可观察、在错误中可解释。

6. 发布前签核清单

  • 两端均固定同一 agent-core tag / commit。
  • 最小测试向量在无网络环境下通过。
  • 至少一个真实 Provider 和一个 mock Provider 通过流式契约。
  • 至少一个 stdio MCP 和一个 HTTP MCP fixture 通过断开/超时测试。
  • 会话截断、配置坏值、取消配对、未知工具四类故障演练有记录。
  • API、配置、JSONL 和 IPC 的破坏性变更均带迁移页与版本号。
  • Charter 与 Tiny Hermes 均已确认不存在私有类型反向渗入公共 crate。

通过本清单仅说明公共合同可供产品接入；产品本身的可用性、安全和发布仍必须分别通过
Charter / Tiny Hermes 文档站的质量门禁。

本页为可离线浏览的重构规范；代码示例是实现合同，不是已交付源码。
