设计原则

  1. Trait 优先：所有抽象通过 Rust trait 定义，实现可替换
  2. 零成本抽象：泛型 + 静态分发，无运行时开销
  3. 错误统一：thiserror 定义错误类型，跨模块传播
  4. 异步优先：Tokio 异步运行时，I/O 密集型任务
  5. 序列化友好：serde 支持 JSON/YAML/TOML

使用方式

作为 git submodule 嵌入（推荐）

agent-core 设计为独立仓库，以 git submodule 形式嵌入 R-Code（R-Code）与 Tiny Hermes：

bash
# 在 R-Code（R-Code）项目根
r-code/ $ git submodule add <agent-core-repo-url> vendor/agent-core

# 在 Tiny Hermes 项目根
tiny-hermes/ $ git submodule add <agent-core-repo-url> vendor/agent-core

# 克隆时带上子模块
git clone --recurse-submodules <r-code-or-hermes-url>

随后在项目根 Cargo.toml（workspace）中以相对路径引用公共 crate：

toml
# r-code/Cargo.toml
[workspace]
resolver = "2"
members = [
    "vendor/agent-core/crates/hermes-core",
    "vendor/agent-core/crates/hermes-llm",
    "vendor/agent-core/crates/hermes-mcp",
    # ... 其他公共 crate
    "crates/r-code-core",
    "crates/r-code-gateway",
    # ... R-Code（R-Code）特有 crate
]
toml
# tiny-hermes/Cargo.toml
[workspace]
resolver = "2"
members = [
    "vendor/agent-core/crates/hermes-core",
    "vendor/agent-core/crates/hermes-llm",
    # ... 其他公共 crate
    "crates/hermes-turn",
    "crates/hermes-tools",
    # ... Tiny Hermes 特有 crate
]

项目内 crate 依赖公共 crate 时，统一通过 workspace 依赖别名：

toml
# crates/hermes-turn/Cargo.toml
[dependencies]
hermes-core = { workspace = true }

完整的 workspace 成员清单与原始包映射见 11-crate-mapping.html，
版本 pin、升级流程和双消费者验收见 13-submodule-and-workspace-integration.html。

重要说明

  • compaction / config / error 不是独立 crate：在现有 small-rust-hermes 中，
    它们内聚在 hermes-core（compaction/error）和 hermes-llm（config）。 本文档集为清晰起见分篇描述，重构时可选择保持内聚或拆分为独立 crate， 两者均可，11-crate-mapping.html 给出了推荐划分。
  • hermes-turn / hermes-tools / hermes-server 属 Hermes 特有：
    turn 编排是 Hermes 的执行引擎（详见 Tiny Hermes 的 Turn 编排）， 不在公共层；R-Code（R-Code）有自己的 Agent Runtime（Pi adapter + 任务状态机）。

下游重构链路

Agent Core 是两个产品包的上游依赖。它不是可选的背景材料，而是 Provider、会话、工具、消息、配置、错误、进程边界和质量门的唯一共享来源。先完成本包 P0–P15，再选择 R-Code（R-Code）或 Tiny Hermes 的产品链路。

P0–P15 Agent CoreC0–C19 R-CodeH0–H15 Tiny Hermes
  1. 公共层：从 总览 到 文档边界与追溯，产出稳定的版本化合同与可验证质量门。
  2. R-Code（R-Code）路线：进入 R-Code HTML 文档站，按 重构运行手册 落地桌面工作区、Agent、工具网关、服务层、验收和发布。
  3. Tiny Hermes 路线：进入 Tiny Hermes HTML 文档站，按 重构运行手册 落地 Rust 多通道代理、记忆、skills、内置工具、服务端和分发。

三包离线交付时，保持以下同级结构并从本页开始：rebuild-delivery/agent-core/、rebuild-delivery/r-code/、rebuild-delivery/tiny-hermes/。如使用 Git 子模块，具体固定版本、workspace 解析、升级和回滚步骤以 子模块与 workspace 集成 为准。

HTML-only 边界：这三个目录中的重构规范和引用资料均以 .html 提供。本文档中若展示 README.md、SKILL.md 或项目内 docs/*.md，它们是在说明最终产品需要处理的用户文件格式，绝不是交付包外的说明文档依赖。
