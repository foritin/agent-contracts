基于 00-overview～15-document-boundary 全部规范生成。覆盖实施步骤（并行 / 串行）、可验证步骤（单元 / 集成 / 契约测试）与验收标准。

DTO 序列化契约

消息与 Provider

V-MSG-01 User(Text) → Assistant(Text) 序列化→反序列化，内容与 role 不变
V-MSG-02 Assistant(ToolUse id=A) 后必须紧接 User(ToolResult id=A)
V-MSG-03 取消发生在 ToolUse 后/ToolResult 前时，补写 is_error=true 的 cancelled 结果
V-PROV-01 stream 依次产生 TextDelta、ToolUse、Usage、Done；不依赖网络分块边界
V-PROV-02 不可恢复错误时流终结，错误带可展示分类，不泄露 API key

ToolHost 与 MCP

V-TOOL-01 未知工具默认拒绝或要求确认，绝不直接执行
V-TOOL-02 同名内置工具与 MCP 工具不碰撞；MCP 使用 server__tool 命名
V-TOOL-03 stdio 子进程退出后，下次调用返回可诊断错误，不损坏会话 writer
V-TOOL-04 Streamable HTTP 超时/非2xx/非法 JSON 映射为稳定错误类别

会话 / 配置 / 压缩

V-STORE-01 JSONL 最后一行只写一半时，恢复保留完整历史并报告截断
V-STORE-02 原子写入中断后，旧/新文件二者之一完整可读，无混合内容
V-CFG-01 默认值 < 配置文件 < 环境变量 < 显式参数 优先级固定且有测试
V-CFG-02 调试输出/错误/支持包不含 api_key、authorization、cookie、token
V-COMP-01 压缩前后最近 user 目标、未完成工具结果、持久事实均可追溯

兼容性与迁移

未知字段策略：旧实现读取含未知字段的未来 fixture 不崩溃（保留或警告）
14 §4
迁移 fixture 至少三份：最早支持版本 / 上一版本 / 含未知字段的未来版本
ToolSpec 新字段不改变旧确认策略；旧 consumer 不执行未知动作

下游消费者验证（非 agent-contracts 范围）

范围边界：agent-contracts 是公共层，只交付合同与公共侧测试。下列“两个下游消费者对同一向量给出一致结果”的验证属产品仓库职责，不在本 crate 勾选范围内（13 §7）。agent-contracts 侧需保证的是：合同稳定、可被任意消费者独立实现并通过。

agent-contracts 侧义务

① 公开 trait / DTO 稳定且有版本策略；② 提供无网络、可重复的公共测试向量（V-*）；③ 不向公共 crate 反向渗入任何产品私有类型；④ 破坏性变更附迁移说明。消费者侧的契约测试由各产品仓库维护。

三、验收标准及验收步骤

▶

阶段验收门

每个 P 阶段须先由两个消费者各写一组契约测试通过后，才允许下一阶段开始（13 §5）。

P0 验收

标准：serde 往返通过；未知字段策略有测试；崩溃后 JSONL 可读取。

步骤：①运行 DTO 往返测试 ②投递含未知字段的 fixture ③构造半行 JSONL 跑 recover。

P1 验收

标准：流式文本/工具调用/取消/usage 事件可录制。

步骤：①MockProvider 回放完整 stream ②触发不可恢复错误验证不泄露 key ③取消后验证配对结果。

P2 验收

标准：工具命名不碰撞；失败默认拒绝/确认；MCP stdio/HTTP 断开可恢复。

步骤：①同名内置+MCP 工具并存 ②调用未知工具 ③杀掉 stdio 子进程后调用 ④HTTP 超时/非2xx。

P3 验收

标准：配置优先级固定；敏感值不打印；长对话摘要不丢关联。

步骤：①四级优先级覆盖测试 ②Debug 输出扫描敏感词 ③压缩后验证 user 目标/工具结果/事实保留。

P4 验收

标准：请求/事件可往返；版本不兼容被拒绝；窗口重启状态可恢复。

步骤：①IPC 请求-响应-事件端到端 ②握手版本不匹配 ③杀进程后重启恢复会话。

P1 阶段门全绿
P2 阶段门全绿
P3 阶段门全绿
P4 阶段门全绿

故障演练（发布前硬门）

四类故障演练

取消配对演练：ToolUse 后取消，验证补写 ToolResult(is_error) 且会话不损坏
进程重启演练：杀进程后 JSONL 可恢复，状态可投影
连接断开演练：MCP stdio/HTTP 断开后可诊断 + 自动重连
坏配置演练：缺字段/空 api_key/不可写目录 → 安全默认 + 明确错误
秘密泄漏演练：诊断包/日志/错误输出扫描，确认无敏感值

性能与资源预算

流式事件不全量复制历史；会话追加为线性写入
14 §5
JSONL 恢复支持流式读取，坏尾行不使整文件失效
MCP 连接/重连/超时有可配置上限
compaction 记录输入范围与摘要来源，可审计
所有 token/字节/深度限制在 DTO 中可观察、在错误中可解释

发布前签核清单

源自 14 §6。agent-contracts 作为公共层只对「公共合同本身」签核；产品可用性/安全/发布由各产品仓库各自质量门负责。

agent-contracts 侧签核（公共合同本身）

最小测试向量在无网络环境下通过
API、配置、JSONL 和 IPC 的破坏性变更均带迁移页与版本号
公共 crate 不含任何产品私有类型（依赖审计：公共 crate 不依赖产品私有 crate，无产品专属 DTO 变体）

下游产品侧签核（非 agent-contracts 范围，由各产品仓库维护）

① 各产品固定同一 agent-contracts tag/commit；② 至少一个真实 Provider + mock 通过流式契约；③ 至少一个 stdio + 一个 HTTP MCP fixture 通过断开/超时；④ 会话截断/配置坏值/取消配对/未知工具四类故障演练有记录；⑤ 两产品可在不读取对方源码条件下凭本文档创建一致接口。这些项不在本 crate 勾选范围内。
